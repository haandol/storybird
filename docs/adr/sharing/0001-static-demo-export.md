# ADR 0001: 정적 HTML 데모를 안전하게 내보낸다

Date: 2026-09-02

## Status

Accepted (2026-09-02)

## Context

사용자는 Storybird 서버나 계정 없이 데모를 전달해야 한다. 캡처 자산과 사용자 입력 문자열을
HTML에 포함하므로 내보낸 파일이 스크립트 실행 경계를 깨거나 프로젝트와 무관한 자산을 복사하면
안 된다. 에디터에서 정한 클릭포인트 캡션과 화면 자막의 위치·배경 스타일도 정적 플레이어에서
달라지면 안내 의미가 훼손된다.

## Decision Drivers

- 내보낸 데모는 로컬 파일과 일반 정적 호스팅에서 동작해야 한다.
- 실행 서버, 데이터베이스, 계정이 필요하면 안 된다.
- 프로젝트 문자열이 HTML이나 JavaScript로 실행되면 안 된다.
- 선택한 프로젝트에 속한 자산만 내보내야 한다.
- 에디터와 네이티브 미리보기에서 보인 텍스트 오버레이가 정적 플레이어에서도 같아야 한다.

## Decision

내보내기는 `index.html`, `demo.json`, `assets/`로 구성된 새 디렉터리를 만든다. 프로젝트
JSON을 플레이어에 포함하되 `</script>` 종료를 이스케이프하고, 런타임은 사용자 문자열을
`textContent`로만 렌더링한다. 자산은 현재 화면 목록에 참조된 파일만 순서 기반 이름으로
복사한다. 정적 플레이어는 공유 모델의 클릭포인트 캡션, 화면 자막 위치, 배경색, 불투명도를
해석하며 빈 텍스트에는 오버레이를 만들지 않는다.

### Requirement Contract

- 내보내기는 네트워크나 Storybird 실행을 요구하지 않는다.
- 기존 대상 디렉터리를 덮어쓰지 않고 고유 이름을 선택한다.
- 사용자 문자열을 HTML로 해석하지 않는다.
- 프로젝트가 참조하지 않는 로컬 캡처는 복사하지 않는다.
- 클릭포인트 캡션은 해당 핫스팟 주변에서 캡처 프레임 안쪽에 표시한다.
- 화면 자막은 선택한 상단 또는 하단 위치에 표시한다.
- 캡션과 자막의 배경색 및 0%부터 100%까지의 불투명도를 내보낸 결과에 보존한다.
- 빈 캡션이나 자막은 정적 문서에 보이는 오버레이를 만들지 않는다.
- Storybird 브랜딩 표시 여부는 프로젝트 설정을 따른다.

## Alternatives

#### Storybird 클라우드 링크만 제공

공유와 분석은 쉬워지지만 서버 운영과 계정이 필요하고 local-first 제품 경계를 깨뜨린다.

#### 단일 HTML에 이미지를 base64로 모두 포함

파일 하나로 전달하기 쉽지만 큰 데모의 메모리와 파일 크기가 급증하고 자산 캐시·검사가 어렵다.

#### 사용자가 템플릿 HTML을 직접 편집

유연하지만 안전한 escaping 계약을 보장할 수 없고 재내보내기 결과가 재현되지 않는다.

#### 텍스트 오버레이를 이미지에 합성

어떤 뷰어에서도 같은 픽셀을 보장하지만 내보낸 뒤 텍스트를 선택하거나 접근성 이름으로 읽을 수
없고, 캡처마다 새 이미지를 생성해야 한다. 구조화된 텍스트와 스타일로 렌더링하는 방식을 채택한다.

## Consequences

- 어떤 정적 서버에서도 배포할 수 있고 오프라인에서도 열린다.
- 네이티브와 웹 렌더러의 오버레이 배치·스타일 동등성을 회귀 테스트해야 한다.
- 내보낸 복사본은 이후 Storybird 편집과 자동 동기화되지 않는다.
- 원격 참여 분석은 제공하지 않는다.
