# ADR 0001: 에디터와 플레이어가 같은 데모 모델을 사용한다

Date: 2026-09-02

## Status

Accepted (2026-09-02)

## Context

녹화 결과는 자동 생성 후 수정할 수 있어야 하고, 미리보기와 내보낸 플레이어가 에디터에서 본
순서·핫스팟·분기·텍스트 안내를 동일하게 해석해야 한다. 화면마다 별도 재생 로직을 두면 편집
결과와 실제 데모가 쉽게 어긋난다. 사용자는 클릭 지점에 짧은 설명을 붙이고 화면 전체의 안내를
상단 또는 하단 자막으로 보여줄 수 있어야 하며, 캡처 내용에 맞춰 배경색과 투명도를 조절해야
한다.

## Decision Drivers

- 한 번 편집한 제목, 클릭포인트 캡션, 화면 자막, 핫스팟, 대상 화면이 모든 플레이어에서 같아야
  한다.
- 분기 대상은 화면 순서 변경과 독립적으로 유지돼야 한다.
- 캡션은 클릭 지점과의 관계가 보이면서 화면 경계 밖으로 벗어나지 않아야 한다.
- 기존 프로젝트의 화면 캡션을 잃지 않고 새 자막 표현으로 이어가야 한다.
- 미리보기 이벤트는 프로젝트별 로컬 분석으로 집계돼야 한다.
- 빈 프로젝트와 삭제된 대상은 안전하게 처리해야 한다.
- 작은 창에서도 화면 선택, 캔버스 편집, 인스펙터의 모든 동작에 접근할 수 있어야 한다.

## Decision

화면과 핫스팟을 UUID 기반 데모 모델로 정의하고 에디터, 네이티브 미리보기, 정적 내보내기가
같은 계약을 사용한다. 핫스팟은 정규화 위치와 선택적 대상 화면 ID를 가진다. 대상이 없으면 다음
화면으로 진행하고 마지막 화면에서는 완료로 처리한다.

각 핫스팟은 선택적 클릭포인트 캡션과 그 배경 스타일을 가진다. 캡션은 핫스팟의 정규화 위치를
기준으로 화면 안쪽 여유가 큰 좌우 방향에 자동 배치하고, 캡처 프레임 안에 유지한다. 각 화면의
기존 캡션은 화면 자막으로 해석하며, 사용자가 상단 또는 하단 위치와 배경 스타일을 선택한다.
배경 스타일은 색상과 0%부터 100%까지의 불투명도를 가진다.

넓은 창에서는 프로젝트 사이드바와 화면 목록·캔버스·인스펙터를 동시에 표시한다. 좁은 창에서는
프로젝트 사이드바를 자동으로 접고 화면 목록을 메뉴로, 인스펙터를 시트로 전환한다. 레이아웃만
바뀌며 편집 가능한 계약은 같게 유지한다.

### Requirement Contract

- 화면 순서 변경은 ID 기반 분기 연결을 깨뜨리지 않는다.
- 화면 삭제 시 그 화면을 가리키는 핫스팟 대상은 안전하게 제거한다.
- 클릭포인트 캡션은 핫스팟별로 독립 편집하며, 빈 값이면 표시하지 않는다.
- 클릭포인트 캡션은 핫스팟 주변에 자동 배치하고 캡처 프레임 밖으로 벗어나지 않는다.
- 화면 자막은 화면별로 독립 편집하며 상단 또는 하단 중 하나를 선택한다.
- 클릭포인트 캡션과 화면 자막은 각각 배경색과 0%부터 100%까지의 불투명도를 조정한다.
- 불투명도 0%는 완전 투명, 100%는 완전 불투명 배경으로 렌더링한다.
- 에디터, 네이티브 미리보기, 정적 플레이어는 텍스트·위치·색상·불투명도를 동일하게 해석한다.
- 새 오버레이 필드가 없는 기존 프로젝트는 기존 화면 캡션을 하단 자막으로 유지하며 안전하게
  열린다.
- 미리보기 시작, 화면 보기, 핫스팟 클릭, 완료 이벤트를 로컬에 기록한다.
- 빈 데모는 재생 실패 대신 명시적인 빈 상태를 표시한다.
- 좁은 창에서 수평 스크롤이나 잘림으로 기능을 숨기지 않는다.
- 프로젝트, 화면, 인스펙터 접근 방식은 바뀔 수 있지만 편집 기능은 모두 유지한다.

## Alternatives

#### 배열 인덱스로 분기를 저장

모델이 단순하지만 화면 재정렬·삭제 때 모든 연결을 다시 계산해야 하며 누락 시 잘못된 화면으로
이동한다.

#### 에디터와 플레이어에 별도 모델 사용

각 화면에 최적화할 수 있지만 변환 단계와 호환성 테스트가 늘고 동작 drift가 발생한다.

#### 선형 다음/이전만 지원

구현은 단순하지만 제품 흐름의 분기와 정보 핫스팟을 표현할 수 없다.

#### 사용자가 캡션 위치를 자유롭게 지정

모든 배치를 표현할 수 있지만 캡션 위치를 별도로 저장·조정해야 하고 클릭포인트 이동 뒤 관계가
쉽게 어긋난다. 클릭포인트 위치에서 화면 안쪽 방향을 자동 선택하는 방식을 채택한다.

#### 프로젝트 전체에 하나의 오버레이 스타일 사용

편집 항목이 적지만 캡처마다 밝기와 정보 밀도가 달라 필요한 대비가 다르다. 클릭포인트와 화면별
안내가 각자의 배경색과 불투명도를 갖도록 한다.

#### 모든 폭에서 세 개의 편집 열을 고정 유지

넓은 창에서는 정보 밀도가 높지만 작은 디스플레이에서 인스펙터와 캔버스가 화면 밖으로 밀려
사용할 수 없게 된다. 좁은 폭에서 탐색 UI를 전환하는 방식을 채택했다.

## Consequences

- 네이티브 미리보기와 정적 플레이어의 계약이 명확하다.
- 프로젝트 스키마 변경 시 기존 데이터 디코딩과 양쪽 플레이어 호환성을 함께 검증해야 한다.
- 캡션 자동 배치는 편집 부담을 줄이지만 사용자가 임의 좌표로 미세 조정할 수는 없다.
- 좁은 폭과 넓은 폭 두 레이아웃을 수동으로 검증해야 한다.
