# ADR 0002: 클릭 이벤트를 인터랙티브 단계로 변환한다

Date: 2026-09-02

## Status

Accepted (2026-09-03)

## Context

Storybird의 핵심 결과물은 영상이 아니라 사용자가 클릭하며 진행하는 데모다. 따라서 녹화 중
각 클릭의 위치, 클릭 순간 사용자가 본 화면, 그 클릭으로 나타난 결과 화면을 순서대로 연결해야
한다. 클릭 좌표만 이벤트 시점에 고정하고 화면은 나중에 읽으면 플레이어에서 핫스팟과 화면 상태가
서로 다른 순간을 나타낸다. 빠른 연속 클릭과 녹화 종료가 겹쳐도 단계 순서와 시점 대응이
유지돼야 한다.

녹화 중에는 에디터가 숨겨지므로 상태와 Stop 동작을 제공하는 HUD가 세션의 유일한 Storybird
조작 지점이다. HUD가 화면 최상단에 밀착되면 메뉴 막대 주변에서 눈에 띄지 않아 사용자가
녹화를 멈추기 어렵다.

사람이 직접 조작하는 세션뿐 아니라 에이전트가 브라우저나 앱을 소프트웨어적으로 조작하는
세션도 같은 결과물을 만들어야 한다. 자동화 클릭은 macOS Input Monitoring에서 물리 마우스
이벤트로 관찰되지 않을 수 있으므로, 운영체제 이벤트를 위조하는 대신 에이전트가 수집한 화면과
정규화 클릭 좌표를 로컬 녹화 번들로 전달하는 입력 경계가 필요하다.

## Decision Drivers

- 최종 플레이어의 핫스팟 위치와 배경 화면이 같은 클릭 순간을 나타내야 한다.
- 선택한 소스 밖의 클릭은 기록하면 안 된다.
- 여러 클릭과 Stop이 겹쳐도 입력 순서와 마지막 결과 화면을 보존해야 한다.
- 녹화 상태와 Stop 동작은 화면을 훑지 않고도 찾을 수 있는 초기 위치에 보여야 한다.
- 사람과 에이전트 녹화는 네트워크나 키보드 입력 없이 같은 프로젝트·핫스팟 계약을 사용해야
  한다.

## Decision

모든 녹화는 하나의 소스와 순서가 있는 화면 목록으로 표현한다. 첫 화면을 첫 단계로 저장한다.
각 사람 클릭은 mouse-down을 관찰한 순간에 이미 도착해 있던 최신 유효 캡처 프레임과 0...1
정규화 클릭 좌표를 한 쌍으로 고정한다. 이 클릭 화면을 현재 단계에 사용하고, 클릭으로 나타난
결과 화면을 다음 단계로 저장한 뒤 현재 단계에 그 새 단계를 가리키는 핫스팟을 추가한다. 다음
클릭이 들어오면 그 클릭 순간의 화면이 다시 현재 단계의 화면이 되므로 각 핫스팟은 실제로
클릭한 화면 위에 표시된다.

사람 녹화는 선택 소스 안의 왼쪽/오른쪽 mouse-down을 관찰하고, 이벤트 콜백에서 고정한 클릭
화면과 좌표를 직렬 큐에서 저장한다. 결과 화면은 다음 단계로 보존한다. Stop은 새 클릭 수집을
먼저 끊고 큐를 모두 비운 뒤 스트림을 닫는다.

녹화 HUD의 초기 위치는 선택한 소스가 속한 화면의 가시 영역을 기준으로 가로 중앙이며, HUD
상단은 가시 영역 상단에서 96pt 아래에 둔다. 세로 공간이 부족하면 HUD 전체가 가시 영역 안에
남도록 하단 경계에서 제한한다. 표시 후에는 사용자가 HUD를 드래그해 옮길 수 있다.

에이전트 녹화는 버전이 있는 로컬 `.storybirdrecording` 파일 패키지로 가져온다. 패키지는
프로젝트 이름, 단일 소스 이름, 순서화된 PNG 화면과 각 후속 화면으로 이어지는 정규화 클릭
좌표를 포함한다. Storybird는 전체 패키지를 검증하고 모든 자산을 앱 소유 저장소에 먼저 기록한
뒤 새 프로젝트를 한 번에 추가한다. 에이전트 스킬은 사용자가 지정한 작업을 실행하면서 초기
화면과 각 클릭 후 화면을 수집하고 패키지를 생성해 Storybird로 연다.

### Requirement Contract

- 입력은 왼쪽/오른쪽 mouse-down만 수집하며 키 이벤트는 관찰하지 않는다.
- 클릭 좌표는 선택한 소스의 top-left 기반 캡처 프레임에 대해 0...1로 정규화한다.
- 선택 범위 밖의 클릭은 무시한다.
- 핫스팟이 표시되는 화면은 해당 mouse-down 콜백에서 확보한 최신 유효 캡처 프레임이어야 한다.
- 큐 처리 시점에 도착한 더 늦은 프레임으로 클릭 화면을 대체하지 않는다.
- 단계와 핫스팟 연결은 클릭 순서를 보존한다.
- 새 단계 자산이 저장되기 전에는 프로젝트가 그 자산을 참조하지 않는다.
- Stop은 처리 중인 클릭 저장을 기다린다.
- 녹화 HUD는 선택 화면 가시 영역의 가로 중앙에서 시작하고, 상단 여백은 96pt다.
- 세로 공간이 부족해도 HUD 전체가 가시 영역 밖으로 나가지 않으며 사용자는 표시 후 이동할 수
  있다.
- 에이전트 녹화 패키지 버전은 `1`이며 화면을 하나 이상 포함한다.
- 첫 화면에는 선행 클릭이 없고, 이후 모든 화면에는 이전 화면 기준의 유한한 `x`와 `y`
  좌표가 각각 0...1 범위로 존재한다.
- 패키지의 모든 화면은 하나의 소스 이름에 속하고 PNG 자산만 참조한다.
- 자산 경로는 패키지 내부의 단순 파일명만 허용하며 절대 경로, 상위 경로, 하위 경로,
  심볼릭 링크를 거부한다.
- 패키지의 모든 화면과 좌표를 검증하기 전에는 프로젝트 라이브러리를 변경하지 않는다.
- 가져오기 도중 실패하면 생성 중인 자산을 제거하고 기존 프로젝트 라이브러리를 유지한다.
- 에이전트 녹화는 새 프로젝트로 가져오며 기존 프로젝트를 덮어쓰지 않는다.
- 에이전트 경로는 Screen Recording과 Input Monitoring 권한을 요구하지 않는다.
- 에이전트 패키지와 스킬은 로컬 파일만 사용하고 네트워크 서버, DOM, 쿠키, 키보드 입력,
  비밀번호나 결제 정보를 녹화 데이터에 저장하지 않는다.
- 사람이 녹화한 세션과 에이전트 패키지는 동일한 단계·핫스팟 그래프를 생성한다.

## Alternatives

#### 전체 영상을 저장한 뒤 클릭 구간을 사후 분석

모션을 완전하게 보존하지만 영상 인코딩, 프레임 추출, 저장 용량과 처리 시간이 커진다. 요구사항은
클릭 기반 단계이므로 불필요한 정보를 대량 저장해 채택하지 않았다.

#### 브라우저 DOM과 이벤트를 직렬화

웹에서는 더 정교한 상호작용을 재생할 수 있지만 네이티브 앱과 데스크톱 창을 지원하지 못하고
민감한 DOM·인증 데이터를 더 넓게 수집한다. 범용 macOS 창 녹화 목표와 맞지 않는다.

#### 클릭마다 독립 비동기 저장

처리량은 높지만 완료 순서가 입력 순서와 달라지고 Stop 직전 작업이 세션 종료 뒤 실행될 수 있어
채택하지 않았다.

#### 클릭 뒤 일정 시간 후 최신 프레임을 클릭 화면으로 사용

결과 화면이 안정될 시간을 주기 쉽지만, 연속 클릭이나 애니메이션이 있으면 좌표와 이미지가 서로
다른 순간을 나타낸다. 클릭 화면은 이벤트 콜백에서 고정하고 결과 화면만 별도 단계로 저장한다.

#### 자동화 클릭을 운영체제 마우스 이벤트로 합성

기존 녹화 경로를 재사용할 수 있지만 이벤트 게시 프로세스의 Accessibility 권한이 추가로
필요하고, macOS 전역 이벤트 모니터가 합성 이벤트를 물리 클릭과 동일하게 전달한다고 보장할 수
없다. 화면과 좌표를 명시적으로 전달하는 패키지를 채택한다.

#### 에이전트가 프로젝트 라이브러리를 직접 수정

앱 변경 없이 빠르게 만들 수 있지만 실행 중인 Storybird와 동시 저장하면 원자적 라이브러리
계약을 깨고 자산 참조가 중간 상태로 남을 수 있다. 앱이 검증과 저장의 단일 작성자가 되도록 한다.

#### 로컬 HTTP 제어 서버

실시간 제어는 쉽지만 제품에 네트워크 수신 경계를 추가하고 실행 중인 앱과 포트 관리가 필요하다.
네트워크가 없는 파일 패키지 가져오기를 채택한다.

## Consequences

- 출력이 편집 가능한 화면/핫스팟 그래프로 바로 만들어진다.
- 핫스팟은 사용자가 실제로 클릭한 순간의 화면 위에 표시된다.
- 녹화 상태와 Stop 동작이 메뉴 막대 바로 아래에 붙지 않아 발견하기 쉽다.
- 에이전트는 물리 입력 권한 없이도 동일한 그래프를 만들 수 있다.
- 패키지 생성과 실제 작업 실행 사이의 일관성은 에이전트 스킬의 캡처 순서 검증에 의존한다.
- 전환 애니메이션 자체는 보존하지 않는다.
- 클릭 화면은 스트림이 mouse-down 콜백까지 전달한 최신 프레임이므로 캡처 주기만큼의 시차는
  남을 수 있다.
