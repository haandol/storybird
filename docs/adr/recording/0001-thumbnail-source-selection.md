# ADR 0001: 썸네일 갤러리에서 녹화 소스를 선택한다

Date: 2026-09-02

## Status

Accepted (2026-09-02)

## Context

사용자는 녹화를 시작하기 전에 전체 디스플레이 또는 특정 창을 명확히 골라야 한다. 창을
하나씩 앞으로 가져와 확인하게 하면 선택 자체가 기록 대상의 상태를 바꾸고, 창이 많은 환경에서
탐색 비용이 커진다. 반대로 현재 포커스 창을 자동 선택하면 무엇이 캡처되는지 확인할 기회가 없다.

## Decision Drivers

- 선택 전에 모든 후보를 한 화면에서 비교할 수 있어야 한다.
- 뒤에 가려진 창을 확인하려고 포커스를 바꿀 필요가 없어야 한다.
- Storybird 자체 UI와 작은 시스템 유틸리티 창은 후보에서 빠져야 한다.
- 선택 창은 작은 디스플레이에서도 마지막 항목에 스크롤로 도달할 수 있어야 한다.

## Decision

Storybird는 녹화 시작 시 전체 디스플레이와 현재 화면에 존재하는 일반 창을 로컬 썸네일로
표시한다. 창 썸네일은 독립 창 캡처로 생성해 포커스를 요구하지 않는다. 사용자가 고른 소스
하나가 세션 전체의 캡처 경계가 된다.

### Requirement Contract

- 한 세션은 디스플레이 하나 또는 창 하나만 대상으로 한다.
- Storybird 자체 창, 오프스크린 창, 지나치게 작은 유틸리티 창은 표시하지 않는다.
- 갤러리는 고정 크기이며 목록이 길면 내부에서 스크롤한다.
- 썸네일과 선택 정보는 외부로 전송하거나 영구 저장하지 않는다.

## Alternatives

#### macOS 시스템 공유 선택기

플랫폼과 일관된 UX와 세션 단위 권한 위임이 장점이다. 그러나 앱이 원하는 카드 밀도, 설명,
필터링, 작은 화면 레이아웃을 제어하기 어렵고 자동 UI 검증도 제한적이라 채택하지 않았다.

#### 포커스된 창 또는 마우스가 있는 디스플레이를 자동 선택

구현과 시작 흐름이 단순하다. 대신 사용자가 실제 경계를 확인하지 못하고, 잘못된 창을 캡처할
위험이 커서 채택하지 않았다.

#### 창을 하나씩 앞으로 가져와 선택

별도 썸네일 캡처가 필요 없지만 선택 과정이 대상 앱 상태를 바꾸고 창 수에 비례해 느려진다.
가려진 창도 독립 캡처할 수 있으므로 채택하지 않았다.

## Consequences

- 선택 전 비교가 빠르고 캡처 경계가 명시적이다.
- Screen Recording 권한이 썸네일 생성 단계부터 필요하다.
- 창 목록과 썸네일 생성 시간이 창 수에 따라 증가한다.
